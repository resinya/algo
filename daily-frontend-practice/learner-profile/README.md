# 学习者能力档案

这个目录用于持续记录学习者当前掌握情况、薄弱项、判断依据和下一步训练方向。它不是每日流水账，也不根据一次失误轻易贴标签。

## 文件结构

```text
learner-profile/
├── CURRENT.md          # 当前能力快照，每次有效评估后更新
└── assessments/        # 每次答题或代码复盘的证据记录
    └── YYYY-MM-DD-*.md
```

`CURRENT.md` 只保留现在仍然有效的结论；`assessments/` 保存结论是如何形成的，方便以后校正。

## 能力状态

- `未评估`：还没有足够证据。
- `需加强`：在基础场景中仍频繁卡住，或需要较强提示才能完成。
- `发展中`：能完成主要逻辑，但边界、表达或稳定性仍有明显遗漏。
- `稳定`：在不同题目中能独立正确使用，并能解释原因。
- `熟练`：能迁移到陌生场景、比较多种方案并处理复杂边界。

每个状态还要附带置信度：`低 / 中 / 高`。状态表示当前判断，置信度表示判断有多少证据支持。

## 观察维度

1. 问题理解与拆解
2. JavaScript 基础与 API
3. 数据结构与算法选择
4. 边界条件与健壮性
5. 时间、空间复杂度
6. 测试、调试与验证
7. 代码可读性与模块设计
8. 面试口述与方案权衡
9. 前端工程与 vibe coding 交付
10. 长期保持：隔一段时间后能否再次独立完成

## 什么时候更新

发生以下任一情况时，新增一份 `assessments/YYYY-MM-DD-*.md`，并同步更新 `CURRENT.md`：

- 学习者在对话中粘贴未完成代码、报错代码或文字答案；不要求先写入仓库。
- 学习者口述思路、复杂度或边界。
- 测试暴露了有代表性的错误。
- 学习者在没有提示或仅少量提示下完成修正。
- 间隔复习证明之前的知识已经保持，或出现遗忘。

## 对话指导如何形成记录

一轮对话式指导可以持续更新同一份评估文件，不必等整道题结束：

1. 记录学习者贴出的题目、代码阶段和自述卡点。
2. 老师只处理一个最小阻塞点，并记录给到的提示级别。
3. 观察学习者能否解释原因、独立修改，以及修改后是否通过验证。
4. 新证据只追加简短摘要，例如“误把值当作索引”或“一级反例后自行修正”，不保存整段聊天副本。
5. 若证据改变了总体判断，立即更新 `CURRENT.md`；否则只积累观察，避免过度判断。

对话证据使用“日期 + 题号/主题 + 卡点摘要”定位。仓库中有对应代码时再附相对路径。

## 证据规则

- 每个结论都要链接到具体题目、代码或回答，不能只写“感觉薄弱”。
- 单次粗心通常只记录观察，不立即定为薄弱项。
- 一个强证据，或至少两个相互独立的普通证据，才能将某维度标为 `需加强`。
- 从 `发展中` 提升到 `稳定`，通常需要在不同日期或不同题型中重复证明。
- “测试通过”不等于完全掌握；还要看是否独立完成、能否解释和能否迁移。
- 没有证据时明确写 `未评估`，不猜测。
- 学习者明确说“这里不会”是重要的自述证据，但仍需通过后续解释、修改或变式题定位究竟缺少概念、语法、拆解方法还是调试能力。

## 与 learning-records 的区别

- `learner-profile/` 记录动态状态，可以随新证据升降。
- `learning-records/` 只记录已经被证明掌握的关键知识、纠正的重要误区或目标变化。
