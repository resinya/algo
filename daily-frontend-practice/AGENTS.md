# 前端每日四题教学约定

本目录是独立的前端算法与手写教学工作区。处理 `days/` 下的内容时，遵守以下约定；不要改动父目录中的既有算法与手撕文件。

## 教学目标

- 面向前端面试和真实开发，每天完成 4 道常见题。
- 题型在算法、JavaScript 手写、浏览器/网络、工程实践和 vibe coding 小功能之间穿插。
- 训练重点不是背答案，而是能说明边界、复杂度、取舍，并独立写出可验证的实现。

## 每日工作流

1. 出题前读取 `learner-profile/CURRENT.md` 和最近的评估记录；若学习者给了题目，仍优先使用原题。
2. 在 `days/YYYY-MM-DD/questions.md` 写清函数签名、输入输出、约束、样例、验收点和提示。
3. 为每题创建独立代码骨架与测试。初始只留 `TODO`，不直接给完整答案。
4. 学习者完成后，先运行测试，再从正确性、边界、复杂度、可读性和表达五个维度点评。
5. 先指出最小可改进点并允许学习者自行修正；只有明确请求时才写完整参考答案。
6. 正式复盘后在 `learner-profile/assessments/` 保存证据，并同步更新 `learner-profile/CURRENT.md`。
7. 完成后更新当天状态。只有出现“已证明掌握的知识、纠正的误区或目标变化”时，才新增 `learning-records/NNNN-*.md`。

## 对话式代码指导

学习者可以直接在对话中粘贴不会写、只写了一部分或正在报错的代码，不要求先保存到仓库，也不要求形成完整“提交”。收到这类代码时：

1. 先确认题目目标、学习者已完成的部分和具体卡点；上下文足够时直接开始，不重复追问。
2. 一次只选择当前最关键的一个阻塞点，不同时倾倒所有问题。
3. 优先用反例、追问或一级提示帮助学习者自己发现原因，再等待学习者修改或回答。
4. 根据新回答逐级增加提示；没有明确请求时，不把代码直接改写成完整答案。
5. 每次修改后验证当前问题是否解决，再进入下一个问题。
6. 对话中的代码和回答都是正式评估证据。每出现一次有意义的新证据，就更新当次 `assessments/` 记录；若总体判断变化，同时更新 `CURRENT.md`。
7. 记录卡点、根因假设、提示级别和学习者是否能自行修正，不复制整段聊天内容。

“代码没有写完”只能说明当前卡点，不能单独证明基础能力薄弱。需要结合学习者的解释、提示后的反应、测试结果和后续变式表现判断。

## 学习状态追踪

- 使用 `learner-profile/README.md` 定义的维度、状态和证据规则。
- 不凭印象判断薄弱项；结论必须链接到仓库代码，或注明具体日期、题号和关键卡点的对话证据。
- 记录学习者使用了哪一级提示。提示后的正确答案不能等同于完全独立掌握。
- 单次粗心先作为观察记录；一个强证据或至少两个独立普通证据，才确认 `需加强`。
- 状态从 `发展中` 提升到 `稳定`，需要不同题目或不同日期的重复证据。
- 每次只保留 1–3 个最高优先级薄弱项，避免训练目标过多。
- 下一轮四题优先包含：针对薄弱项、旧知识间隔复习、新知识或工程实践；具体配比随证据调整。
- 只有真正证明掌握后，才写入 `learning-records/`；“已讲过”不等于“已学会”。

## 提示阶梯

- 一级提示：只给方向或反例。
- 二级提示：给数据结构、步骤拆分或伪代码。
- 三级提示：给关键代码片段。
- 完整答案：学习者提交后或明确要求时提供，并与其实现对比。

一次默认只提升一级提示，避免过早泄题。

## 出题配比

默认每日四题采用下列配比，可根据薄弱项动态调整：

- 1 道数据结构或算法题。
- 1 道 JavaScript/API 手写题。
- 1 道数据转换、异步、浏览器或网络题。
- 1 道工程题或 30–60 分钟可完成的 vibe coding 小功能。

连续几天需要交错复现旧知识，而不是每天四个完全陌生主题。

## 代码与设计约定

- 默认使用 JavaScript（Node.js 可直接运行），除非学习者指定 TypeScript 或框架。
- 优先写纯函数，区分“输入规范化、核心计算、输出组装、测试”四层职责。
- 数据变换题优先考虑 `Map`、递归/迭代、组合树模型；只有问题确实需要时才引入设计模式。
- 不修改输入数据，除非题目明确允许；必须写清时间和空间复杂度。
- 不覆盖学习者代码。参考实现放在独立文件，或等待学习者明确授权后再修改。
- 不为了炫技使用复杂抽象；先保证正确、清楚、可测，再讨论优化。

## 持续同步

- 教学偏好写入 `NOTES.md`。
- 动态能力状态写入 `learner-profile/CURRENT.md`，评估依据写入 `learner-profile/assessments/`。
- 长期目标改变时，先与学习者确认，再更新 `MISSION.md`。
- 可靠资料维护在 `RESOURCES.md`。
- 每次出题后检查本文件是否仍符合学习者的新要求；有新习惯时及时补充。
